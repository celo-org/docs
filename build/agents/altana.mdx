This page is for agent developers who want an agent to move stablecoins onchain from a wallet the owner keeps, under limits the blockchain enforces. Altana is built by Altana Network, not by Celo. Altana runs on Celo mainnet. Relay fees can be paid in a stablecoin the wallet holds; the KeyStore registration fee is paid in CELO.

## Prerequisites

- [Bun](https://bun.sh) 1.1 or later for the MCP server
- An MCP client such as Claude Code or Cursor
- A key for the wallet owner, kept on your machine. Altana does not receive it.

## How it works

1. The owner creates a Smart Agentic Wallet. The owner holds the admin key. Altana never holds keys or funds.
2. The owner grants the agent a session key: a scoped, time-bounded delegation from the admin key. The agent signs with the session key only.
3. A session carries three limits: a spend cap per token over a rolling period, an allowlist of contracts and methods, and an expiry. The wallet contract enforces them on the calls the session sends. A call outside them reverts. The spend cap does not bound x402 payments the session signs; see [Pay for x402 APIs on Celo](#pay-for-x402-apis-on-celo).
4. By default, a grant registers the session's public key in the KeyStore, a public onchain registry. Any client can then check that a session key is valid, and the owner revokes a session in one transaction. A revoked session cannot be reactivated.
5. An intent relay turns the agent's intents into transactions and simulates each one before signing.

Wallet addresses are the same on every chain Altana supports, and permissions work the same way on each.

## Connect the MCP server on Celo

`@altananetwork/mcp` exposes wallet and session tools to an MCP client. Use it to operate wallets from a chat interface and to prototype. One server process serves one chain; select Celo mainnet with `ALTANA_CHAIN`.

<Warning>
The MCP server holds the owner's admin key as well as session keys. Its `wallet_execute` tool submits calls signed by the admin key, so an agent connected to the server can act as the owner, and session limits do not bind it. Keep the admin key off the machine where the agent runs.
</Warning>

  <Tab title="Claude Code">

    # Celo mainnet (42220)
    claude mcp add altana -e ALTANA_CHAIN=celo -- bunx @altananetwork/mcp

    Restart Claude Code after you add the server.
  </Tab>

To test first, use `ALTANA_CHAIN=celo-sepolia` (chain ID `11142220`) and get test CELO from the [Celo Sepolia faucet](https://faucet.celo.org/celo-sepolia). To change chain, restart the server with a different value.

The server stores wallet and session keys in the OS keychain, then in `~/.altana/keys.json`, then in environment variables. Keys stay on your machine.

## Use the SDK

`@altananetwork/sdk` exports `CELO` (chain ID `42220`) and `CELO_SEPOLIA` (chain ID `11142220`) from 1.0.0; earlier versions have no Celo config. Install 1.1.0 or later to pay a session grant's relay fee in a stablecoin: the `feeToken` option on `grantSession` arrives in 1.1.0.

```bash
npm install @altananetwork/sdk@^1.1.0 viem
```

```ts
// Celo mainnet (42220)
import { createClient, CELO } from "@altananetwork/sdk";

const client = createClient({ chains: [CELO] });
```

Wallet creation, session grants and revocation follow [Altana's SDK setup](https://docs.altana.network/sdk/setup).

## Pay for x402 APIs on Celo

An agent can pay [x402](/build/agents/x402) endpoints on Celo from its Altana wallet in USDC, USD₮ or USA₮. Pass the tokens as `x402Tokens` when you grant the session, then call `fetchWithX402`, which signs one payment and retries the request once. Altana's [x402 payments](https://docs.altana.network/sdk/x402) page shows the full grant and call.

<Warning>
x402 payments are signed by the session key rather than sent by the session as calls, so the session's daily spend caps do not bound them. A session granted with `x402Tokens` can sign payments in those tokens until it expires or is revoked. Give it a short expiry and fund the wallet only with what the agent should spend.
</Warning>

Run `fetchWithX402` server side, because many endpoints block the payment header in browsers.

## Sell over x402 on Celo

`@altananetwork/x402-server` lets a merchant charge for an endpoint over [x402](/build/agents/x402) on Celo. It ships token configs for `USDC_CELO`, `USDT_CELO` and `USAT_CELO` on mainnet; `USAT_CELO` needs 0.4.0 or later. All three use 6 decimals, so a price of `200_000n` is 0.2. A merchant can list several tokens, and each payment settles on its own token's contract.

Settlement can go through the Celo facilitator at `https://api.x402.celo.org` (Celo Sepolia: `https://api.x402.sepolia.celo.org`). Set `facilitatorService` on the merchant. With the Celo facilitator, eip3009 payments settle through it and it pays the gas. The merchant still needs its own RPC and key. `POST /settle` needs an API key from [x402.celo.org](https://x402.celo.org). See [Settling through Celo's facilitator](https://docs.altana.network/sdk/x402-server#settling-through-celos-facilitator).

## Pay relay fees in a stablecoin

The intent relay sends each transaction and the wallet pays the relay back. On Celo the wallet can pay that relay fee in CELO or in a stablecoin the relay lists; `client.feeCurrencies()` returns the list. This is the relay's own fee, not Celo [fee abstraction](/build/fee-abstraction/overview), which is the other way to pay gas in a stablecoin on Celo.

The KeyStore registration fee is paid in CELO, whatever token pays the relay fee. A grant that registers a session key in the KeyStore pays it, so keep CELO in the wallet for grants. The KeyStore controller's `getRegistrationFeeInWei()` returns the current amount; Altana's [Networks](https://docs.altana.network/concepts/networks) page lists the controller address.

## Set limits that fit the task

Set both `calls` and `spend` when you grant a session. If you leave out `calls`, the session can reach any contract, bounded only by its spend cap. Spend caps do not bound x402 payments, so give a session that pays x402 a short expiry. Spend limits are in a token's smallest unit, so check the token's decimals on Celo first: USDC and USD₮ use 6, USDm uses 18. Limit amounts per token over a period such as a day, and give every session an expiry.

## Troubleshooting

| Symptom | Fix |
|---|---|
| TypeScript syntax error when the server starts | You ran `npx`. Use `bunx` and confirm Bun 1.1 or later is installed. |
| The agent acts on the wrong network | The server uses the chain set at startup. Restart it with the right `ALTANA_CHAIN`. |
| The wallet registers an ERC-8004 agent identity you did not want | Set `ALTANA_AGENT_IDENTITY=off`. |
| A call reverts at validation | The call is outside the session's allowlist, spend cap or expiry. Grant a new session with the limits you need. |
