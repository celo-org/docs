This page is for agent developers who want an agent to move stablecoins onchain from a wallet the owner keeps, under limits the blockchain enforces. Altana is built by Altana Network, not by Celo. Altana runs on Celo mainnet, where fees can be paid in a stablecoin the wallet holds, so the agent needs no separate CELO balance.

## Prerequisites

- [Bun](https://bun.sh) 1.1 or later for the MCP server
- An MCP client such as Claude Code or Cursor
- A key for the wallet owner, kept on your machine. Altana does not receive it.

## How it works

1. The owner creates a Smart Agentic Wallet. The owner holds the admin key. Altana never holds keys or funds.
2. The owner grants the agent a session key: a scoped, time-bounded delegation from the admin key. The agent signs with the session key only.
3. A session carries three limits: a spend cap per token over a rolling period, an allowlist of contracts and methods, and an expiry. The wallet contract enforces them. A call outside them reverts.
4. Grants are registered in the Keystore, a public onchain registry. Any client can check that a session key is valid, and the owner revokes a session in one transaction. A revoked session cannot be reactivated.
5. An intent relay turns the agent's intents into transactions and simulates each one before signing.

Wallet addresses are the same on every chain Altana supports, and permissions work the same way on each.

## Connect the MCP server on Celo

`@altananetwork/mcp` exposes wallet and session tools to your agent. One server process serves one chain; select Celo mainnet with `ALTANA_CHAIN`.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    # Celo mainnet (42220)
    claude mcp add altana -e ALTANA_CHAIN=celo -- bunx @altananetwork/mcp
    ```

    Restart Claude Code after you add the server.
  </Tab>
  <Tab title="Other clients">
    ```json
    {
      "mcpServers": {
        "altana": {
          "command": "bunx",
          "args": ["@altananetwork/mcp"],
          "env": { "ALTANA_CHAIN": "celo" }
        }
      }
    }
    ```
  </Tab>
</Tabs>

To test first, use `ALTANA_CHAIN=celo-sepolia` (chain ID `11142220`) and get test CELO from the [Celo Sepolia faucet](https://faucet.celo.org/celo-sepolia). To change chain, restart the server with a different value.

The server stores wallet and session keys in the OS keychain, then in `~/.altana/keys.json`, then in environment variables. Keys stay on your machine.

## Use the SDK

`@altananetwork/sdk` 1.1.0 or later exports `CELO` (chain ID `42220`) and `CELO_SEPOLIA` (chain ID `11142220`). Earlier versions have no Celo config.

```bash
npm install @altananetwork/sdk@latest viem
```

```ts
// Celo mainnet (42220)
import { createClient, CELO } from "@altananetwork/sdk";

const client = createClient({ chains: [CELO] });
```

Wallet creation, session grants and revocation follow [Altana's SDK setup](https://docs.altana.network/sdk/setup).

## Sell over x402 on Celo

`@altananetwork/x402-server` lets a merchant charge for an endpoint over [x402](/build/agents/x402) on Celo. It ships token configs for `USDC_CELO`, `USDT_CELO` and `USAT_CELO` on mainnet, which use 6 decimals, so a price of `200_000n` is 0.2. A merchant can list several tokens, and each payment settles on its own token's contract.

Settlement can go through the Celo facilitator at `https://api.x402.celo.org` (Celo Sepolia: `https://api.x402.sepolia.celo.org`), which broadcasts the payment and pays the gas, so the merchant needs no RPC endpoint or funded key. Set `facilitatorService` on the merchant. `POST /settle` needs an API key from [x402.celo.org](https://x402.celo.org). See [Settling through Celo's facilitator](https://docs.altana.network/sdk/x402-server#settling-through-celos-facilitator).

## Pay gas in a stablecoin

On Celo the relay takes its fee in CELO or in a stablecoin the wallet holds: USDC, USD₮, USA₮ or EURm. Rates come live from the onchain fee currency directory. See [fee abstraction](/build/fee-abstraction/overview) for how gas in a stablecoin works on Celo.

## Set limits that fit the task

Set both `calls` and `spend` when you grant a session. If you leave out `calls`, the session can reach any contract, bounded only by its spend cap. Spend limits are in a token's smallest unit, so check the token's decimals on Celo first: USDC and USD₮ use 6, USDm uses 18. Limit amounts per token over a period such as a day, and give every session an expiry.

## Troubleshooting

| Symptom | Fix |
|---|---|
| TypeScript syntax error when the server starts | You ran `npx`. Use `bunx` and confirm Bun 1.1 or later is installed. |
| The agent acts on the wrong network | The server uses the chain set at startup. Restart it with the right `ALTANA_CHAIN`. |
| The wallet registers an ERC-8004 agent identity you did not want | Set `ALTANA_AGENT_IDENTITY=off`. |
| A call reverts at validation | The call is outside the session's allowlist, spend cap or expiry. Grant a new session with the limits you need. |
