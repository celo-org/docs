## Overview

The CGTv2 upgrade for the Celo network moves CELO, the network's gas token, from the OP Stack's legacy custom gas token design to Custom Gas Token v2 (CGT v2). It is a maintenance upgrade with no new features. It aligns Celo with the custom gas token design that current OP Stack releases support, so that Celo can adopt future OP Stack upgrades.

## Specifications

Optimism introduced CGT v2 for new chains in [Upgrade 18](https://docs.optimism.io/notices/archive/upgrade-18) ([op-contracts v6.0.0](https://github.com/ethereum-optimism/optimism/releases/tag/op-contracts/v6.0.0)) without a migration path for chains on the legacy design. The Celo CGTv2 upgrade adds that migration for Celo. For full technical details of CGT v2, see the Optimism documentation linked below.

- [Optimism's Custom Gas Token documentation](https://docs.optimism.io/op-stack/features/custom-gas-token)
- [Optimism's Custom Gas Token Specifications](https://specs.optimism.io/protocol/custom-gas-token/overview.html)
- [Optimism's Upgrade 18 Notice](https://docs.optimism.io/notices/archive/upgrade-18)

### L1 contract changes

The guardian pauses the system before the upgrade. One governance transaction then moves the L1 CELO held by `OptimismPortal2` into a new `CeloGasBridgeL1` escrow contract, upgrades the L1 contracts to op-contracts v6.0.0 and enables the custom gas token mode. Moving the CELO makes `CeloGasBridgeL1` emit `EscrowSeeded`, which activates the L2 changes. The system stays paused until the L2 upgrade has succeeded.

CELO deposits go through `CeloGasBridgeL1` instead of `OptimismPortal2.depositERC20Transaction()`, which is removed. In custom gas token mode, `OptimismPortal2` rejects deposits and withdrawals that carry value.

The governance proposal is TBD.

### L2 changes

The upgrade activates in the first L2 block whose L1 origin contains the `EscrowSeeded` event. That block contains only deposit transactions. They install the CGT v2 predeploys `NativeAssetLiquidity` (`0x4200000000000000000000000000000000000029`) and `LiquidityController` (`0x420000000000000000000000000000000000002a`), which hold and release native CELO, and the Celo-specific `CeloGasBridgeL2` (`0x42000000000000000000000000000000000007ef`), which pairs with `CeloGasBridgeL1`. They also upgrade `L1Block`, `L2ToL1MessagePasser` and the sequencer fee vault to their CGT v2 versions.

A final deposit funds `NativeAssetLiquidity` with 1,000,000,000 CELO minus the amount moved into `CeloGasBridgeL1`. CELO withdrawals start from `CeloGasBridgeL2` instead of `L2ToL1MessagePasser`, which rejects withdrawals that carry value.

If an upgrade transaction fails, nodes build the block without the upgrade and CGT v2 stays inactive. While the system is paused, the `SystemConfig` owner can request another attempt from L1.

Native CELO and the CELO ERC-20 are unchanged, so [token duality](/operate/specification/token-duality) works as before.

## Upgrade timelines

The CGTv2 upgrade will activate on Celo Sepolia first and then on Mainnet, with the activation process for each network occurring independently. Each activation follows the L1 governance transaction, so there is no activation timestamp.
